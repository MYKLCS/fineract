## 1 — Crate & Package Topology (Rust Workspace)

```
backend/
  Cargo.toml           # Workspace manifest
  crates/
    common/            # Error types, shared utils, tracing setup
    db/                # Diesel schemas & connection pool
    core/              # Tenant, authentication, i18n helpers
    clients/
    loans/
    savings/
    charges/
    rates/
    tax/
    accounting/
    documents/
    reporting/
    progressive_loan/
    investor/
  api/                 # Axum HTTP host (binary crate)
  integration_tests/   # `cargo nextest`
```

Each domain crate owns:
1. `schema.rs` (Diesel table definitions)
2. `models.rs` (Serde-friendly structs)
3. `service.rs` (pure domain logic)
4. `handler.rs` (Axum route layer)

## 2 — Initial PostgreSQL Schema (high-level)

```
clients(
  id UUID PK,
  external_id TEXT UNIQUE,
  branch_id UUID FK -> branches.id,
  first_name TEXT,
  last_name TEXT,
  dob DATE,
  status TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
)

loans(
  id UUID PK,
  client_id UUID FK -> clients.id,
  product_id UUID FK -> loan_products.id,
  principal NUMERIC(19,4),
  interest_rate NUMERIC(9,4),
  status TEXT,
  disbursed_at TIMESTAMPTZ
)

loan_transactions(
  id UUID PK,
  loan_id UUID FK -> loans.id,
  txn_type TEXT,
  amount NUMERIC(19,4),
  txn_date TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT now()
)

-- …similar for savings, charges, accounting entries, etc.
```

Diesel migrations will live under `backend/migrations/` and be autogenerated via `diesel-cli`.
